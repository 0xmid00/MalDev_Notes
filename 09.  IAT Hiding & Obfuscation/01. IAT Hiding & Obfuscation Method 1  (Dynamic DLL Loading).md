## Dynamic DLL Loading

Loads a Windows API function at runtime using `GetProcAddress` and `GetModuleHandleA` so that the target function does not appear in the binary's Import Address Table (IAT). The function is cast to a matching typedef and called through the resulting function pointer. This prevents the function name from showing up as a static IAT entry visible to PE analysis tools.

> **Limitations:** The function name string (e.g. `"VirtualAllocEx"`) still exists as a plaintext string in the binary and can be detected by string scanning. `GetProcAddress` and `GetModuleHandleA` themselves will appear in the IAT, which is itself a detectable signature. Future techniques address both of these remaining indicators.

**Usage**

Define a `typedef` matching the target function's signature, then call `GetProcAddress` with the DLL handle and the function name string to resolve the address at runtime. Cast the result to the typedef and call it through the function pointer.

- `IN LPCSTR szModuleName`  Name of the DLL that exports the target function (e.g. `"KERNEL32.DLL"`).
- `IN LPCSTR szFunctionName`  Name of the exported function to resolve (e.g. `"VirtualAllocEx"`).

**Return Value**

`FARPROC`  `GetProcAddress` returns the address of the resolved function, or `NULL` on failure. The caller casts it to the matching function pointer typedef before use.

**External Files**

- `windows.h`  `HANDLE`, `LPVOID`, `SIZE_T`, `DWORD`, `FARPROC`, `WINAPI`, `GetProcAddress()`, `GetModuleHandleA()`, `GetLastError()`
- `stdio.h`  `printf()`

### Code

```c
#include <windows.h>
#include <stdio.h>

// Define a typedef matching the exact signature of the target function.
// The function pointer is used to call the resolved API without a static IAT entry.
typedef LPVOID(WINAPI* fnVirtualAllocEx)(
    HANDLE  hProcess,           // Handle to the target process.
    LPVOID  lpAddress,          // Desired base address; NULL lets the OS choose.
    SIZE_T  dwSize,             // Size of the allocation in bytes.
    DWORD   flAllocationType,   // Allocation type (e.g. MEM_COMMIT | MEM_RESERVE).
    DWORD   flProtect           // Memory protection (e.g. PAGE_READWRITE).
);


// Resolve and call VirtualAllocEx at runtime — no static IAT entry is created.
LPVOID DynamicVirtualAllocEx(HANDLE hProcess, LPVOID lpAddress, SIZE_T dwSize, DWORD flAllocationType, DWORD flProtect)
{
    // Resolve the target function address from the already-loaded DLL.
    // GetModuleHandleA does not increment the DLL's reference count.
    fnVirtualAllocEx pVirtualAllocEx = (fnVirtualAllocEx)GetProcAddress(
        GetModuleHandleA("KERNEL32.DLL"),   // DLL that exports the target function.
        "VirtualAllocEx"                    // Function name — still a plaintext string in the binary.
    );
    if (pVirtualAllocEx == NULL) {
        printf("[!] GetProcAddress Failed With Error : %d \n", GetLastError());
        return NULL;
    }

    // Call the resolved function through the function pointer.
    return pVirtualAllocEx(
        hProcess,           // Handle to the target process.
        lpAddress,          // Desired base address.
        dwSize,             // Size of the region to allocate.
        flAllocationType,   // MEM_COMMIT | MEM_RESERVE etc.
        flProtect           // Page protection flags.
    );
}
```

**Example**

```c
// Allocate RW memory in the local process without a static VirtualAllocEx IAT entry.
LPVOID pAddress = DynamicVirtualAllocEx(
    GetCurrentProcess(),        // Target: current process.
    NULL,                       // Let the OS choose the base address.
    4096,                       // Allocate one page.
    MEM_COMMIT | MEM_RESERVE,   // Reserve and commit in one call.
    PAGE_READWRITE              // Read/write access.
);

if (pAddress == NULL)
    printf("[!] Allocation failed\n");
else
    printf("[+] Allocated at 0x%p\n", pAddress);
```

**Parameter Sources**

No external parameter sources — the module name and function name strings are compile-time constants supplied directly by the caller.
